# Передача дел: где что лежит и как продолжать

Этот файл для того, кто продолжит работу. Цель проекта — декомпиляция
Crash Bandicoot 3 (`SCUS_942.44`, американская версия) с побайтовым
совпадением и затем порт на ПК. Общий план — в `docs/roadmap.md`, как
декомпилировать — в `docs/decompiling.md`.

## Правила

- Файлы игры никогда не коммитятся: `disc/`, `asm/`, `assets/`, `build/` в
  `.gitignore`. Исполняемый файл каждый кладёт свой (`disc/README.md`).
- Коммит — только когда `make` печатает «OK, совпадает с оригиналом».
  `make NON_MATCHING=1` тоже должна собираться (и печатает «НЕ совпадает» —
  это нормально). Ошибка `.org backwards` значит, что функция на C длиннее
  оригинала: её имя добавляется в `config/us/nm_too_long.txt`.
- При каждом заметном шаге обновляются цифры в `README.md` и
  `docs/roadmap.md` (`make progress` даёт точные).
- Игру не пересоздаём с нуля и читов не добавляем: только декомпиляция и порт.

## Состояние

- Код игры (C-файлы `src/*.c`): 307 функций из 409 совпадают побайтово,
  91 написана на C без совпадения (работают как оригинал, сверено вручную),
  11 остаются ассемблером в отдельных сегментах (менеджер памяти и мелкие
  функции инициализации). Все C-файлы кода игры целиком на C.
- Функции без совпадения, их оценки и что с ними уже пробовали —
  `docs/nm_status.md`. Большинство отличаются только выбором регистров.
- Исполнитель байткода GOOL (сегмент `gool_asm`) переписан на C для порта:
  `src/goolvm.c`. Проверен против оригинала в эмуляторе MIPS:
  `tools/goolvm_test.sh` (2000 случайных программ совпали).
- Ручной ассемблер Naughty Dog (сегмент `nd_asm`, ~46 КБ: память,
  математика, столкновения, отрисовка через GTE) — начат перевод на C:
  `src/nd.c` (sin, cos, суммы квадратов), проверка `tools/nd_test.sh`.
  Опись всех 74 точек входа и план — `docs/nd_asm.md`.
- Библиотеки PSY-Q (`psyq`) не декомпилируются: для порта они заменяются
  слоем `src/pc/` (таблица в `docs/roadmap.md`, этап 4).

## Где что лежит

| Путь | Что там |
|------|---------|
| `src/*.c` | код игры; функции без совпадения — в `#ifdef NON_MATCHING` |
| `src/goolvm.c`, `src/nd.c` | C-версии ручного ассемблера для порта (не линкуются в сборку PlayStation) |
| `include/` | заголовки: структуры игры (`game.h`, `gool.h`, `ns.h`, `gfx.h`, …), `gte_inline.h` (GTE-макросы) |
| `config/us/` | `splat.yaml` (нарезка), `symbol_addrs`, `nm_too_long.txt`, контрольная сумма |
| `tools/` | сборочные скрипты; `tools/decomp/` — инструменты доводки до совпадения (см. его `README.md`); тесты C-версий в эмуляторе (`goolvm_test.sh`, `nd_test.sh`) |
| `docs/decompiling.md` | процесс и все найденные приёмы совпадения |
| `docs/nm_status.md` | функции без совпадения: оценки и заметки |
| `docs/nd_asm.md` | опись сегмента `nd_asm` и план его перевода |
| `docs/drafts/` | незаконченные черновики, которые лучше текущей версии в `src/`, но ещё не совпали (`func_80035410.c`: с `goto` разница только в регистрах двух последних веток) |

## Как продолжать

1. Подготовка: `make setup`, положить свой `SCUS_942.44` в `disc/`,
   `make extract`, `make` (должно быть «OK»).
2. Доводка функций до совпадения: начинать сверху `docs/nm_status.md`,
   инструменты — `tools/decomp/README.md`. Заметки в таблице говорят, что уже
   не помогло. Найденный приём записывать в `docs/decompiling.md`.
3. Перевод `nd_asm` на C: следующий шаг — функции без GTE из
   `docs/nd_asm.md` (копирование/очистка, столкновения). Каждую добавлять в
   `FUNCS` в `tools/nd_difftest.py` (для функций с указателями нужен свой
   генератор аргументов и сравнение памяти) и проверять `tools/nd_test.sh`.
   Потом программный GTE — без него не проверить функции отрисовки и не
   запустить порт.
4. Проверка сборки `make NON_MATCHING=1` в эмуляторе (DuckStation,
   PCSX-Redux) требует полного образа диска; в облачном окружении его не было.

## Замечания

- Тесты в эмуляторе ставят Python-пакет `unicorn` в `.venv` сами. В
  unicorn деление на ноль работает не как на R3000; тест исполнителя GOOL
  поправляет это для оригинала (см. `tools/goolvm_difftest.py`).
- Скрипты сравнения заменяют адреса переходов на `<tgt>`, поэтому
  «разница 0» ещё не совпадение: проверяет только полная сборка.
- `tools/decomp/inst.sh` ставит функцию в текущий файл. Не ставьте функции
  из старых копий файлов (`BASE`): так однажды откатилось уже сделанное
  совпадение (исправлено, см. историю `ns.c`).
