# Сегмент nd_asm: ручной ассемблер Naughty Dog

`0x80039E3C–0x80045750`, около 11 800 инструкций. Это не код компилятора, а
ассемблер, написанный вручную: копирование и очистка памяти и таблиц
порядка, математика (sin/cos, квадратный корень, длины), столкновения с
поверхностями зон и вся отрисовка моделей и зон через GTE. Для PlayStation
он остаётся ассемблером; для порта его нужно переписать на C, как
исполнитель GOOL (`src/goolvm.c`).

Порядок работы: функция переводится в `src/nd.c` (в сборку PlayStation этот
файл не входит), её проверка добавляется в `tools/nd_difftest.py`, и
`tools/nd_test.sh` сравнивает её с оригиналом в эмуляторе MIPS. Функции с
GTE так проверить нельзя (в unicorn нет GTE): для них нужен программный GTE,
его стоит написать первым шагом этой части (он всё равно нужен порту).

Splat склеил почти весь сегмент в одну «функцию» под меткой данных
`ticks_elapsed`; настоящие начала ниже найдены по вызовам из C и изнутри
сегмента. Размер — до следующей известной точки входа, поэтому у части
строк в него входят ещё безымянные функции (например, `0x8003AEEC`:
(x² + y² + z²) >> 20, уже переведена).

Что дальше:

1. Простые функции без GTE. Готовы: копирование `8003A928`, очистка таблицы
   порядка `8003AC44`, счётчик тиков `8003AE70`, корень `8003D9DC`, суммы
   квадратов, sin/cos, вся цепочка столкновений с поверхностями зоны
   (`8003AF78` обход октодерева → список коробок → `8003B874`, `8003BBF0`,
   `8003BD18`, `8003C04C`). Также `80039E3C`/`8003A234` (применение и откат дельт списков полуслов). Все функции `nd_asm` без GTE готовы.
   Тест `tools/nd_test.sh` (5000/500 случайных случаев на функцию) и
   мутационные проверки: испорченная копия каждой функции ловится.

Уточнения к таблице:

- `8003D9DC` (квадратный корень) — всего 19 инструкций без GTE (переведён).
  С `0x8003DA2C` идёт безымянная функция отрисовки, это её инструкции GTE
  попали в строку корня.
- `8003A884`–`8003A904` и `8003AB9C`–`8003AC1C` — не отдельные функции, а
  хвосты развёрнутых циклов копирования, на которые прыгают
  `80039E3C`/`8003A234` и `8003A928`.
- `80039E3C` применяет дельту списка полуслов (удаления, вставки, затем
  перестановки), `8003A234` отменяет её (перестановки задом наперёд, потоки
  в обратных ролях); формат описан в `src/nd.c`. Оригинал после команды XOR
  оставляет адрес вместо индекса базы относительной перестановки — C-версия
  повторяет это.
2. Программный GTE — сделан: `src/pc/gte.c` (`include/gte_soft.h`). Команды,
   которые использует игра (RTPS, RTPT, NCLIP, AVSZ3/4, DPCS, DPCT, MVMVA, GPL,
   плюс OP, SQR, GPF, INTPL), регистры с их особенностями чтения и записи,
   флаги, делитель с таблицей UNR. Написан по описанию железа (psx-spx);
   самопроверка — `tools/pc/gte_selftest.c` (проекция, NCLIP, AVSZ3, делитель
   против точного деления: отличие до 3 в 1 случае из ~30000, это свойство
   алгоритма). Сверить с настоящим железом здесь нечем.
3. Функции отрисовки (`8003C3D0`, `8003C990`, `8003E000`, `80040ED8`,
   `80043050` и остальные с GTE). Проверка готова: `tools/gte_hook.py`
   собирает `src/pc/gte.c` в библиотеку для хоста, заменяет инструкции COP2
   (mtc2/mfc2/ctc2/cfc2/lwc2/swc2 и команды) на nop и выполняет каждую перед
   её местом через этот GTE (работает и в слотах задержки). Так оригинал и
   C-версия, которые используют один и тот же GTE, сравниваются как функции
   без GTE. Уже применено к опкоду 0x51 исполнителя GOOL (и нашло там
   расхождение в C-версии: переполнение индекса глубины). Первая функция
   отрисовки с GTE на C: `8003F520` (поворот точек матрицей модели). C-код
   обращается к GTE через `include/gte_api.h`: встроенный ассемблер COP2 для
   PlayStation и тестов, вызовы `src/pc/gte.c` в порте. В тесте перехват GTE
   ставится только на проверяемые функции (`GTE_RANGES` в
   `tools/nd_difftest.py`): каждый перехват замедляет каждую инструкцию.
   Короткие куски между `8003F5D8` и `8003F8A4` — внутренние помощники
   большого отрисовщика (работают с его регистрами), отдельно не переводятся.
   Помощники матриц `80041EF0`, `80041F18`, `80041FBC`, `80041FD8` берут
   матрицу в t0..t4; в C они получают указатель на неё, а тест вызывает
   оригинал с регистрами и сравнивает результат и всё состояние GTE.
   Высоты рельефа: `800450D4` (высота и наклон в точке, два треугольника
   клетки, GPL), `80044CA0` (движение через стенки клеток, затем высота) и
   их помощник `80044F74` — на C, проверены. Матрица модели `8003C3D0`
   (камера × поворот × масштаб, проверка видимости) — на C; тест сравнивает
   и всё состояние GTE (`GTE_STATE` в `tools/nd_difftest.py`). Поиск листа
   октодерева по точке `8003C990` — на C (сама функция короткая,
   `8003C990`–`8003CB24`; дальше в строке описи — безымянный отрисовщик).
